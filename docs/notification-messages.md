# 主动推送文案

主动推送只有两类，均仅发送给通过指令订阅的会话：

| 类型 | 数据来源 | 含义 |
| --- | --- | --- |
| 重置预告 | `data.scheduled_reset` | 网站记录了明确重置公告，尚未确认执行 |
| 已执行重置 | `data.latest_reset` 或历史接口 | 网站已记录执行事件 |

`active_watch` 是概率预测，只在状态查询中显示，达到 100% 也不主动推送。预告没有概率字段。预告和后续执行各推送一次；仅预定时间已到或预告消失，不会生成已执行提醒。

## 重置预告

以下是排版示例，不代表实时数据。预告显示类型和预定时间，保留网站数据来源。标题、说明、时间信息与数据来源之间留一空行；类型和预定时间在同一数据块内逐行显示。预定时间为空时显示“未给出预定时间”。

```text
【Codex 重置预告】

已发布明确的重置预告，尚未确认执行。

类型：常规重置
预定时间：2026/10/25 18:41 (UTC+08:00)

数据来源：https://codex-resets.com
```

## 已执行重置

以下为排版示例，时间标签使用“重置记录时间”。数值取自 `announced_at`，表示公告／首次观察时间，不能当作精确执行时间。

```text
【Codex 已执行重置】

网站记录了重置事件，请检查你的实际额度。

重置记录时间：2026/10/25 14:06 (UTC+08:00)

数据来源：https://codex-resets.com
```

没有 `scheduled_reset` 时不产生预告。新订阅默认不补发订阅前已有的已执行记录。`meta.generated_at` 和统计数字变化不会生成新通知。

## 订阅和取消

简体中文使用 `重置订阅开启` 开启订阅，使用 `重置订阅关闭` 关闭订阅；两者都支持 `/` 前缀。`重置状态` 包含当前信号、最近 3 次历史和订阅状态。

后台确认过的执行事件不会在后续轮询或重启后重新作为预告发送。状态校验失败或退避期间，尚未发送的预告保留队列、暂停发送；校验恢复后确认仍有效才继续投递。已执行重置的重试不受这项预告暂停规则影响。

必要的历史补查会覆盖已观察预告的原公告时间，包括仍残留在状态接口中的当前预告。历史确认执行后，不再重试该预告，并按订阅规则发送执行提醒；不会把扩大查询范围带回的无关旧记录补发给当前会话。

```text
订阅成功，当前会话将接收重置预告和已执行重置提醒。推送语言：简体中文。
```

```text
取消成功，已停止当前会话的重置推送。
```

两种成功操作各回复一条确认，不额外发送测试消息。新订阅的首次正常检查如果发现待执行预告，可按正常规则发送预告。

## 其他语言与平台

- 五种语言均采用相同分块排版；简繁中文 UTC+8，日语和韩语 UTC+9，英语 UTC。
- 事件类型为 `banked` 时，简体标题为“【Codex 储备重置已发放】”，繁体为“【Codex 儲備重置已發放】”；预告与历史的类型名称为“储备重置／儲備重置”。这是发放通知，不表示已经立即执行。
- 所有平台均省略公告正文、依据和原始来源链接，与来源种类、链接长度无关；Discord 和 Telegram 仍保留[平台限长保护](platforms.md)。
- 待发送和重试的结构化通知在发送时按当前语言渲染；已发送事件不重放。
- 预告发送失败时，仅在当前状态仍确认该预告待执行的情况下重试。
