# 重置状态文案

以下三版是排版示例，不代表实时数据。使用 `重置状态`、`/重置状态` 或其他语言的状态指令查询。信号区按以下顺序三选一：

1. 有 `scheduled_reset`：显示待执行公告，即使预定时间为空或已到；不同时显示概率预测或无预测提示。
2. 没有公告且 `active_watch.expires_at` 晚于查询时间：显示有效预测。
3. 没有公告，且预测为空或已过期：显示“当前无有效重置预测。”。有效期等于查询时间也视为过期。

## 有待执行公告、未订阅

即使同时存在有效的 `active_watch`，也只显示以下公告区：

```text
【Codex 重置状态】

待执行公告：2026/10/25 18:41
预定时间已到也不代表已完成，需等待执行证据。

最近 3 次重置（公告／首次观察时间）：
1. 2026/10/25 14:06 — 常规重置
2. 2026/10/24 01:00 — 常规重置
3. 2026/10/23 01:00 — 常规重置

以上时间均为 UTC+08:00。

当前会话未订阅。
发送「重置订阅开启」接收重置预告和已执行重置提醒。

数据来源：https://codex-resets.com
```

## 其他状态

已订阅时，将两行订阅引导替换为以下内容。语言名称按实际保存或固定配置的语言显示：

```text
当前会话已订阅：接收重置预告和已执行重置提醒。
推送语言：简体中文。
```

简体中文三指令为 `重置状态`、`重置订阅开启`、`重置订阅关闭`。关闭订阅会清除当前会话的待发送和待重试提醒。

- 预测区仅展示 `level`、`reset_chance_percent`、`expires_at`，不显示引文、预测窗口和原始来源链接。概率为 `null` 显示“未提供”，`0` 仍显示“0%”。后台继续校验完整数据，但不将预测加入推送队列。
- 有待执行公告时，信号区只显示预定时间和“预定时间已到也不代表已完成，需等待执行证据。”；未给时间则显示“未给出预定时间”。不会将待执行公告放入已执行历史，也不会因预定时间已到而切换为预测。
- 历史按事件类型和 ID 去重、时间倒序，最多三条；没有记录时明确显示暂无记录。历史接口失败时显示失败提示，并在状态接口可用时显示其已知的最近重置。
- 状态接口失败时显示失败提示，不将失败误报为“无预测”；仍显示可用历史和本地订阅信息。
- 五种语言采用相同结构。简繁中文 UTC+8，日语和韩语 UTC+9，英语 UTC；状态消息末尾统一标注一次时区。不显示响应生成时间、历史引文和重复的最新重置行。

主动推送只有[重置预告和已执行重置](notification-messages.md)，不推送概率预测，包括 100% 预测。通知不显示网站公告原文、依据或原始来源链接；标题、说明、时间信息和网站数据来源之间留一空行。订阅与取消成功仍各回复一条对应语言的确认。
