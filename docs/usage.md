# 使用与配置

## 安装与更新

Linux / Docker 的安装和 QQ 验收流程见 [Docker 与 QQ 实测步骤](docker-qq-testing.md)，Telegram、Discord 的接入要求见[平台与权限](platforms.md)。

需要 Node.js 22.12 或以上、Koishi 4.18.11 或兼容版本，以及可用的 `database`、`http` 服务。数据库请使用持久化驱动，例如 SQLite、MySQL 或 PostgreSQL；测试使用的内存驱动不会保留重启前的数据。

发布到 npm 并被 Koishi 市场收录后，在控制台“插件市场”搜索 **codex-resets**，安装后在“插件配置”中添加并启用 `codex-resets`；后续版本可通过市场更新。首次发布后的索引收录可能需要等待，是否已公开发布请以 npm 注册表查询结果为准。[Koishi 发布说明](https://koishi.chat/zh-CN/guide/develop/publish)

也可以在 **Koishi 实例目录** 使用现有包管理器安装注册表版本，例如：

```sh
npm install koishi-plugin-codex-resets@latest --registry https://registry.npmjs.org/
```

从本地 `.tgz` 切换到注册表版本时，执行上面的命令（Yarn 实例使用对应的 `yarn add`），再重启 Koishi。订阅保存在数据库中，无需重新注册。

维护者发布流程见 [发布与验证](publishing.md)。日常本地提交与普通推送不改变版本号，也不创建标签、Release 或启动 CI。只有明确发布正式 GitHub Release 时，工作流才检查、构建并发布 npm。

### 使用本地安装包

已发布版本使用对应 Release 的原始安装包，保存在项目的 `packages/releases/`；从源码构建测试包时，按[开发与本地打包](development.md#项目内安装包目录)运行 `npm run release:pack`，默认输出到 `packages/test/` 下的新建目录，保留已有正式安装包。

在 Koishi 实例目录中，使用该实例现有的包管理器安装上述目录里的 `.tgz`。npm 示例（替换项目路径和实际构建目录）：

```sh
npm install /path/to/plugin-project/packages/test/BUILD_DIRECTORY/koishi-plugin-codex-resets-0.5.3.tgz
```

将示例路径替换为本次实际输出位置。然后在控制台添加并启用插件；Docker 和其他包管理器的安装方法见 [Docker / QQ 验收](docker-qq-testing.md)。

## 配置

数据库和机器人适配器应已单独配置：

```yaml
plugins:
  codex-resets:
    locale: auto
    pollIntervalMs: 300000
    requestTimeoutMs: 15000
    sendIntervalMs: 1000
```

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `locale` | `auto` | 自动跟随订阅指令语言，或统一指定 `en-US` / `zh-CN` / `zh-TW` / `ja-JP` / `ko-KR` |
| `pollIntervalMs` | `300000` | 检查间隔，单位毫秒，最短 60 秒 |
| `requestTimeoutMs` | `15000` | 单次 API 请求超时 |
| `sendIntervalMs` | `1000` | 主动发送的最小间隔，跨批次生效；QQ 官方适配器实际使用至少 `3100` 毫秒，包含 URL 降级重试 |
| `qqGroupManagers` | `[]` | QQ 官方群角色不可用时的备用授权，精确绑定登录机器人 ID（非 AppID）、群 OpenID 和用户 OpenID；留空仅校验平台角色，已确认的普通成员仍拒绝。配置本身不订阅。见[配置步骤](platforms.md#qq-官方适配器) |

平台和适配器需要支持主动发送；私聊还需要支持创建私聊频道。未连接实际机器人前，不能确认特定平台的主动发送权限。

## 三条指令

在需要接收通知的会话中发送完整指令。支持 **`/` 前缀、无前缀和实例原有前缀**，例如 `/重置订阅开启`、`重置订阅开启`。消息中仅包含指令片段、引用指令或 @其他机器人的消息不会通过兼容入口触发。Koishi 的全局权限、会话过滤和别名过滤仍然生效；禁用或删除某个别名后，其无前缀和 `/` 形式也不再触发。

| 简体中文指令 | 作用 | 群聊 / 频道权限 | 私聊权限 |
| --- | --- | --- | --- |
| `重置状态` | 优先显示待执行公告，其次有效预测，以及最近 3 条历史、会话订阅状态与推送语言 | 所有用户 | 所有用户 |
| `重置订阅开启` | 开启当前会话订阅，接收重置预告和已执行重置提醒，保存指令语言 | 平台群主／管理员；QQ 官方群角色不可用时可用备用授权 | 所有用户 |
| `重置订阅关闭` | 关闭当前会话订阅并清除待发送、待重试消息 | 平台群主／管理员；QQ 官方群角色不可用时可用备用授权 | 所有用户 |

订阅成功只回复一条对应语言的确认信息，取消成功也只回复一条确认信息；**不会额外发送模拟通知或测试消息**。重复订阅会回复已订阅及当前语言，未订阅时取消会如实提示未订阅。首次轮询会按正常规则发送当前仍待执行的真实预告；概率预测只在状态查询中展示，即使为 100% 也不主动推送。

状态查询不会创建订阅、改变推送语言或消费通知记录。历史按公告／首次观察时间倒序显示，最多 3 条；该时间不一定是精确执行时间。状态或历史接口单独失败时，仍展示另一个接口的可用结果和本地订阅信息。

状态使用精简文字模板，按顺序选择一个信号区：有 `scheduled_reset` 时显示待执行公告及其未确认执行提示；没有公告时才显示未过期的 `active_watch`，包含等级、概率和有效期；两者均不可用时显示“当前无有效重置预测。”。预定时间为空或已到不影响公告优先级，预测有效期等于当前时间则视为过期。历史只显示时间与类型，不重复展示最新一条、不显示引文和响应生成时间。整条消息统一标注一次时区；历史查询失败时保留状态接口中已知的最近重置。完整示例见[状态文案](status-messages.md)。

指令不接受其他群号、用户 ID 或额外参数。普通群聊订阅由该群共享，Telegram 话题和 Discord 频道各自独立；私聊只属于当前用户。Telegram 话题按所属群与话题共同区分，不同群中相同编号的话题互不影响。推送只发送到执行订阅的会话。

### 群管理员权限

- QQ / OneBot：平台返回的 `owner` 或 `admin`。
- QQ 官方适配器（`qq`）：优先检查事件角色，再查询群成员接口；`owner`、`admin` 放行，`member` 拒绝。角色不可用时才使用 `qqGroupManagers` 备用授权，不能覆盖已确认的普通成员身份；不适用于 QQ 频道（`qqguild`）。
- Telegram：`creator` 或 `administrator`，通过平台接口查询。
- Discord：服务器所有者或具有 `ADMINISTRATOR` 权限的成员。
- 身份不匹配、超时或尚未支持群权限校验的适配器：拒绝群聊订阅和取消。角色缺失或接口失败也默认拒绝，QQ 官方群可按上述规则使用备用授权。拒绝不会改变已有订阅，状态查询和私聊指令仍可使用。

本插件不设置最低 Koishi 用户等级；Koishi 等级 0 的用户也能查询或在私聊管理订阅。提高 Koishi 用户等级不会赋予群管理员身份或 QQ 官方群授权。QQ 角色不可用且无备用授权、用户未获授权、适配器不支持、权限查询失败分别返回对应的五语言提示。平台配置、原生斜杠指令及适配器限制见[平台与权限](platforms.md)。

## 语言与推送

指令、回复、通知和配置说明支持 English、简体中文、繁體中文、日本語、한국어。默认 `locale: auto` 按订阅指令保存当前会话的推送语言；状态查询跟随查询指令语言。固定语言配置对所有会话的回复和通知生效。

完整指令表、语言切换和时区说明见[语言指南](languages.md)；首次订阅、预告与执行通知的去重、补查和重试见[推送规则](notifications.md)。
